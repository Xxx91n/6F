# R66-Q1 深度调研题面（grill R66 第一轮第一题：③+④ 合并裁定）

## 裁定问题 verbatim

在一个以「预声明守卫断言」为核心信任模型的 Node.js 工程仓中，裁定两条写码纪律的冲突边界 + 一项验证立法的形态。

## 背景（本仓实物，全部已核实）

1. **「zero-backslash 纪律」**：本仓以 Node fs.writeFileSync 写文件为唯一写盘通道，既有写入卫生惯例要求正则/模式字面尽量用字符类或 charCode 替代反斜杠，防嵌套写入吞义。该纪律目前是卫生惯例级（未见独立立法 D 记录）。
2. **P0-2 死正则事故**：为遵守该纪律，一处守卫断言的正则被写成 /not_in_preview:[ ]*\[[^]]*'(Micro-A|Macro-C)'/ ——其中 [^]] 在 JS 语义中：[^] = 否定空字符类 = 匹配任意字符，其后 ] 为字面量——整个否定字符类实际含义变成「任意字符后加字面 ]」，与原意「非 ] 字符序列」完全不同，死正则永不命中预期模式（审计窗发现的真红，已修）。
3. **修复版**：/not_in_preview:[ ]*\[[^\]]*'(Micro-A|Macro-C)'/ ——证明在 JS 否定字符类内排除 ] 物理上无法零反斜杠（[^\]] 与 [^\x5D] 皆含反斜杠）。
4. **85-check A4 先例（已自发落码）**：修复断言内嵌活性正对照——assertion 表达式末尾直接接 NIP_ROGUE_RE.test("x = { not_in_preview: ['Macro-C'] };")，即用合成违规串证明判别臂活着（判别臂死亡即红，防「改了但没验」第三次复发）。
5. **仓内制度面**：决策账本 decision-ledger.md（D-001~D-212，217 条 current）、docs/adr 24 件、CONTEXT.md 词条；已有 ADR-0013 预声明验证包纪律（正负对照先行）、D-169/D-171 Accepted Risk 五要件、D-177 比例化预声明（按风险定声明面大小）、D-142 摄入分诊四态等。本仓问题主线不是「要不要仪式」而是「仪式的比例与边界」。

## 候选裁定

- **(a) 合流立法**：①边界句成文——「zero-backslash 纪律适用域=字符串字面量与模板串的写入语境；不适用于正则字符类内部，否定字符类含裸 ] 必须转义」＋可机检伴生断言（[^] 起头/否定字符类内裸 ] 形态=红）；②变异击杀按比例立法——「修复性断言」（为验证某 fix 新增/改写的断言）须附变异击杀证据：P0/P1 级修复=强制内嵌活性正对照（A4 形），P2+=预声明内读数可代；正则/模式匹配类断言不分级皆强制内嵌。
- **(b) 最小补丁**：仅成文「否定字符类内 ] 必须转义」单条（不立边界总则）；变异击杀维持自发实践不立法。
- **(c) 全面立法**：边界句＋所有断言不分级强制内嵌正对照。
- **(d) 仅登记不裁**：两纪律冲突记 known-issue，下次复发再裁。
