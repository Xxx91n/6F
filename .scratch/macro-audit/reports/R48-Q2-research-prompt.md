# R48-Q2 调研题面 —— 「预声明验证包」工序收严裁量（D-147 工序形态：声明时序证据强度＋诱导实跑必选性）

（提交 atomcode-research 深调研；账本=唯一事实源立场，调研须回顾 decision-ledger 全部 current 记录、docs/adr、CONTEXT.md 词条、工业界成熟落地心智模型为重点。）

## 背景

本仓为五尺度工程内容审计产品的 spec-level 规划+治理仓。D-147（R35-Q4 判例，current）建制「探测面修语义须预声明验证包」工序：探测面（check/guard 脚本）语义级变更前，先预声明验证判据包（预期断言/红态诱导面/升格条件），再实施变更。原判例形态=声明钉在裁定账行（D-147③款）→变更落独立实施 commit。

## 缝的实证（r48 审计呈报 P2/P3，不阻断但建议入裁量）

- **P2 声明时序证据弱化**：R48 执行批对 33-check.mjs 增 J 组断言（探测面变更）时，预声明验证包与变更**同 commit（7bd2e8e1）原子落盘**。审计判「实质合规」（声明四要素齐备＋变更原子可回滚），但呈报观察：同 commit 落盘使「先声明后实现」只能信作者自述时序，评审者无法从工件区分预声明与事后合理化；原判例「声明钉账行→变更另 commit」则时间序在 git 历史上自证。
- **P3 声明-兑现分离洞**：执行窗预声明了红态诱导面（断言须在构造病态输入下真红）但未留实跑读数——审计窗以沙箱副本补证 5/5 才闭环。若审计窗不补证，该包=只声明未验证形态流出。

## 候选

(i) 双收严：①预声明验证包须独立先落 commit（声明 commit 先于变更 commit——时序 git 可证）；②红态诱导实跑读数列必选复验件（声明了诱导面就必须实跑留数，未跑=包不闭环按缺件处置）。利=证据强度官方语义＋闭环硬约束；弊=工序变重，小变更须多切 commit。
(ii) 半收严：只收 P3——诱导实跑列必选复验件；声明位置不动（账行/报告节钉声明即可，不强制独立 commit）。利=堵真洞保弹性；弊=时序证据强度维持弱档。
(iii) 不收严：本轮形态判实质合规已足，两建议降为文书口径（建议级非约束级）。利=工序最薄；弊=同型弱化可再犯且无拦。
(iv) 换锚：声明锚=账行/审计报告节等「先于变更 commit 落盘的物化面」即合法（不强制独立 commit）＋诱导实跑列必选复验件。利=证据强度等 (i) 而工序最薄（声明物化先于变更落盘即自证时序）；弊=探测面变更若非由裁条驱动则账行锚不在场——适用面窄。

## 调研要求

1. 工业界成熟心智模型（重点）：predeclared/pre-registered 协议的成熟惯例——科研预注册（OSF preregistration）对「声明先于执行」的证据学要求与时间戳机制；TDD「先写测试」的 commit 时序惯例（test commit 先行 vs 同 commit）；RFC/design-doc 先行于实现的治理惯例；安全/SRE 域「预声明 kill criterion/验证判据」的先声明后执行纪律；声明与实现同 commit 原子落盘 vs 分时落盘在审计证据强度上的取舍先例；「声明了验证件就必须实跑留数」的惯例（声明-兑现闭环）。
2. 判候选：四候选各评强弱——特别裁决：①「预声明」的证据学本质是时序可证还是物化先于变更即足（commit 序 vs 文档序的等效性）；②红态诱导实跑是否应列必选复验件（声明而不跑的 fail-closed 断言包在工业验证纪律中的定位）；③工序收严的成本-收益平衡判据（何时值得多一道工序）。
