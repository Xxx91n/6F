# R49-Q2 调研题面 —— 冻结声明件内扩面的合规通道立法（D-177 首个适用实例名实缝隙处置）

（提交 atomcode-research 深调研；账本=唯一事实源立场，调研须回顾 decision-ledger 全部 current 记录、docs/adr、CONTEXT.md 词条、工业界成熟落地心智模型为重点。）

## 背景

本仓=五尺度工程内容审计产品的 spec-level 规划+治理仓。D-177（刚立法）规定「预声明验证包」工序：探测面/生成面变更须先落声明物化面（账行/报告节/独立预声明文件合法）先于变更 commit——同 commit 原子落盘不满足证据强度（时序可证=本质）；红态诱导面声明即含实跑义务。

首个适用实例即出名实缝隙（轮49 审计 F2）：预声明包B 落盘先于一切变更（锚本体合规），但执行中发现三处冻结声明外扩面且全程无勘误注记：①载体漂移——声明写确定性函数增入 check-kit.mjs，实落 env-contract.mjs（名义更贴但与声明不符）；②断言增项——声明断言组 A1~A4+B1/B2，实落多出未声明的 A5 熵源钉；③语义扩面——某提交锚字段语义从「取 HEAD」改为「钉 criteria 锚 commit」——超名义变更面且预声明反列其为「合法漂移」。方向全正确、报告透明披露为「追加发现」，但冻结声明外扩面无合规通道可依——首例即定形。

本质张力：预声明的证据学内核=「声明物化先于变更落盘→时序可证」（参照预注册研究 time-locking、审计 contemporaneous documentation 原则）。扩面=执行中才发现，天然不可能预先声明——唯一能选的是扩面被物化承认的位置与时点。

## 候选

(i) 勘误追加单通道：声明文件设 append-only「勘误」节（链式追加不改写原文）——扩面发现后先落勘误 commit（追加扩面条目＋发现时点字段）再走变更 commit；扩面与变更同 commit 不可分割时勘误紧随其后且「发现时点」如实标 post-hoc（晚于变更落盘）。声明↔落地在 git DAG 上永远可查；commit body 声明/报告节追述均不算数。利=时序证据链对扩面段同样成立＋晚发现诚实化；弊=执行中须停一手落勘误，工序最重。
(ii) 变更 commit body 扩面声明通道：扩面在变更 commit body 内显式声明。利=零新工序；弊=原洞对扩面段重开——body 与变更同原子落盘，先声明后实现只能信自述时序。
(iii) 分级双轨：机械偏差（载体位置/断言计数等实现层名实缝）走 commit body；语义扩面（规格/判据/行为面）强制勘误追加 commit。利=按重量分级；弊=「机械 vs 语义」判据歧义成新裁面（首例三处扩面两处分类存疑）。
(iv) 不立法：报告「追加发现」节惯例即足。利=零约束；弊=审计已判不充分——同类缝隙先例化。

## 调研要求

1. 工业界成熟心智模型（重点）：预注册/规约冻结后发现偏差时的合规处置惯例——临床研究 protocol deviation/amendment 规程（deviation vs amendment 区分、时点登记义务）；预注册研究的 registered report deviation 披露惯例；航空/医疗变更控制的「先勘误后实施」惯例；RFC/spec errata 机制（IETF errata 追加不改写原文）；审计行业的 scope expansion 追加程序与记录惯例；变更管理里 change-order 时点纪律（实施前 vs 实施后补票的合规差）；SRE/工程 post-hoc documentation 的证据效力边界。
2. 判候选：四候选各评强弱——特别裁决：①「先勘误后变更」是否行业标准强约束（还是允许变更后补勘误并标时点）；②commit-body 声明对扩面段的证据强度在审计学上的定位；③「机械偏差 vs 语义扩面」分级是否存在可操作判据先例；④晚发现扩面的「诚实晚声明 vs 伪装早声明」惯例处置。
3. 冲突扫描：结论是否与本仓 current 决策冲突（重点 D-177 预声明验证包工序〔刚立法——勘误通道是其延伸还是修订〕、D-146⑤ 勘误链式追加不改写、D-148③ 生效时点不溯既往、D-139/D-140② 分 commit 纪律、D-144①④ 账行↔编年随行、D-147 scoped revised 形态）。
4. 推荐+理由+置信度；缺口如实标位。
