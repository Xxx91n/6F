# R50-Q4 调研题面 —— 文件换代时哨兵字标（守卫断言面）防丢建制

## 背景

本仓=五尺度工程内容审计产品的 spec-level 规划+治理仓。守卫面=61 件 check 脚本＋guard-all-run 总跑器；任务书制：grill 轮产出常驻任务书 .scratch/macro-audit/handoffs/next-round.md，每轮换代为整体重写。

哨兵字标面实证：13 件 check 断言 next-round.md 内容——正向子串钉（#45/demo/#39/#40 等落点记录）、定点正则（41a-check 断言「T6 分发收尾·仓内文档面（#41a/R6-03…）✅ DONE 2026-09-16」逐字行形态）、负向断言（42-check：禁「无 ✅ 的 #42 行」）。任务书已有「历史票面闭环索引（守卫锚点留痕）」保护区节集中存放滚动断言；44-check 头注明文「票面滚动断言——字面钉随任务书换代维护」。

近红实证：R49 收口换代整体重写时漏掉 #45 落点行→45-check H5 红→补回→复跑全绿。被接住靠的是「先跑守卫再 commit」的工序顺序侥幸——约定存在但未入换代规程/模板（只活在 check 注释里），每次换代靠写者记得保钉。

## 候选

(i) 换代工序条文＋保护区钉死：WORKFLOW 换代节加步「先 grep next-round 断言钉（含负向断言形态）→新书落盘逐钉核对在场→守卫跑兜底」＋任务书模板钉「历史票面闭环索引」节为保护区（整节保搬只增不删）。利=防线前移＋成本≈一条 grep；弊=盘点步仍半人工。
(ii) 机检盘点件：写工具脚本自动抽 check 源内断言钉生成核对清单。利=穷举不依赖人工；弊=断言形态多样（子串/正则/负向/多行逻辑）解析易漏——工具自身成新风险面。
(iii) 守卫兜底够用不立规：已实证接住；换代本就跑守卫。利=零新规；弊=依赖工序顺序侥幸＋每次漏钉烧修复回路。
(iv) 断言面迁账本：check 改断言 decision-ledger（append-only 天然不丢）。利=根除钉丢面；弊=动 13 件 check 断言语义（D-177 重活）＋handoff 落点记录是票面对账合法钉点。
(倾向 (i)：约定升格换代规程；守卫保持兜底；负向断言须入盘点清单。)

## 调研要求

1. 工业界成熟心智模型（重点）：文件重生/再生成场景下断言面保护的惯例——「generated file + hand-editable region」模式的成熟实现（如 Android R.java vs 用户区、protobuf 生成物与 hand-edit 分离、IDE 项目文件 protected regions、codegen markers）；「契约测试/断言锚定文件内容」在文档文件上的先例（markdown-lint 断言、文档哨兵字符、changelog 完整性检查）；guardian/守护测试作为兜底网 vs 生成端预防工序的分层先例（测试兜住 vs 工序防住的分工惯例）；「保搬区/preserved section」模式在模板换代中的先例（DEADBEEF sentinel、keep-alive blocks、DO NOT EDIT 区外保搬标记惯例）；人类可写的「重要串」清单管理惯例（manifest 化 vs 隐式埋点）；轮换/滚动文件中历史记录迁移的约定（rolling window 文件中历史锚点保搬）。
2. 判候选：四候选各评强弱——特别裁决：①「换代前盘点断言钉→换代后逐钉核对」工序步是否有先例（verify-preserved-markers 惯例）；②保护区节（reserved/preserved section）作为哨兵集中位的先例与优劣；③自动抽取断言清单工具化的先例与陷阱（解析断言形态的复杂度）；④负向断言（禁含形态）在哨兵字标管理中的先例；⑤守卫兜底「接住就够」模式的事故先例（先写后查 vs 先查后写）。
3. 冲突扫描：结论是否与本仓 current 决策冲突（重点：D-177 预声明、D-149 守卫组、44-check 头注既约「字面钉随换代维护」、D-146⑤ append-only、D-148③ 生效时点、handoff 任务书建制、D-185 开工对表、D-186 降级形态立法）。
4. 推荐+理由+置信度；缺口如实标位。
