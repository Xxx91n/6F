# R49-Q4 调研题面 —— 微修处置裁量：探测面守卫的 false-green 危险方向修复 vs 缓挂

（提交 atomcode-research 深调研；账本=唯一事实源立场，调研须回顾 decision-ledger 全部 current 记录、docs/adr、CONTEXT.md 词条、工业界成熟落地心智模型为重点。）

## 背景

本仓=五尺度工程内容审计产品的 spec-level 规划+治理仓。守卫面=静态 node check 集（.scratch/architecture-recovery/reports/NN-check.mjs 40+ 件，guard-all-run 全量闸）。D-177 立法：探测面/生成面变更须先落预声明验证包物化面（比例化——变更小声明面可小）。D-169：Accepted Risk 缓挂须五要件（判据引用/不修理由/补偿控制/具名裁者/到期+复审钩），缺一=静默丢弃态。

审计轮49 呈报两个微修 finding（探测面守卫自身缺陷）：
- **F3（危险方向）**：d179-check.mjs 用手搓注释剥离正则（strip // comments via regex）——与同源 46-check.mjs A18 初版同型反模式：A18 初版因 regex 内未转义引号进 phantom-string 态吞行，造成 75a-check C2 真败＋389↔389 dangling 计数失配（本仓已实证事故并修复为 charcode 扫描）。d179-check 当前实测绿但断言语义=文件级意图断言（run_at env 注入核验）——注释吞行即可吞真实违规=false-green 危险方向（守卫失效无告警）。修法=移植已验证的 stripComments 例程（46-check A18 修复件同型），便宜。
- **F4（安全方向但便宜）**：A18 NONPLAIN_START 指标集不含 '#'，且不追踪块标量区段（'|'/'>' 内 '#' 属内容非结构）——false-red 安全侧（绿不藏真错）但指标清单与自身规则文档口径不齐（文档声称 shell 式 '#' 注释触发亦覆盖）。修法=补 '#' 指标＋块标量区段跳过，小改。

裁点=修 vs 缓挂 Accepted Risk（AR 五要件登记成本≈修复成本）；若修→走 D-177 预声明（声明面按变更大小比例化）＋实施中扩面走 D-181 勘误通道（刚立法）。

## 候选

(i) 双修小批量：F3+F4 各随紧凑预声明进微修批——F3 危险方向必修（吞行即守卫失效无告警）；F4 便宜且消口径不齐名实缝。利=两洞清零＋AR 注册税省；弊=一个微修批工序成本。
(ii) 只修 F3，F4 缓挂 AR：危险方向必修＋安全方向缓行（复审钩=下次 A18 触碰时）。利=批次最小；弊=F4 AR 五要件成本≈修复成本＋口径不齐存续。
(iii) 只修 F4，F3 缓挂：反向错配——危险方向洞敞开。不取。
(iv) 双双缓挂 AR：最贵无收益（两件修复都便宜，F3 危险方向）。不取。

## 调研要求

1. 工业界成熟心智模型（重点）：守卫/静态分析器自身缺陷的处置惯例——lint/static-analysis 工具的 false-negative（漏报）vs false-positive（误报）风险方向分级惯例（漏报=危险向必修 vs 误报=烦人但安全）；测试基础设施自身 bug 的修复优先级惯例（test infrastructure bugs vs product bugs——守卫失效型缺陷是否天然高优先）；已知危险模式在同代码库多处的「同型缺陷普查」惯例（反模式复制体是否应一次性肃清）；「当前绿但实现有缺陷」的缺陷分类（latent defect/dormant bug 处置惯例）；小修复批量打包 vs 单独修的工程惯例。
2. 判候选：四候选各评强弱——特别裁决：①false-green 探测面缺陷是否惯例性不可缓挂（AR 缓挂对危险方向缺陷是否合法态）；②false-red 缺陷缓挂 AR 的合理性（安全方向+便宜修复下 AR 是否仍劣于直接修）；③「同型反模式普查」是否有先例支持主动全肃；④微修批的合理打包边界。
3. 冲突扫描：结论是否与本仓 current 决策冲突（重点 D-169/D-171 AR 五要件＋到期形态、D-177 预声明工序、D-181 勘误通道〔刚立法〕、D-180 收口 commit 对〔刚立法〕、D-175② 工作面序、D-144①④ 账行↔编年、D-140②/D-139 分 commit 纪律、D-179 减负包语义〔F3 正是其 check 文件〕）。
4. 推荐+理由+置信度；缺口如实标位。
