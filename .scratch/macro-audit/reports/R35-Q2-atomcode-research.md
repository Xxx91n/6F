## 2) 分点结论

**2.1 (a) 工序内化=业界标准解，有官方一手先例**：actions/javascript-action 官方模板（check-dist.yml 原文已读）对「dist 进仓＋忘再生」的完整答案就是两层——README 把「npm run all（含 build）」标为「This step is important! If you do not run this step, your action will not work correctly」强制本地工序（=产生面工序内化进官方贡献文档）＋check-dist.yml CI rebuild-diff 硬闸（与本仓 D-067③ 逐字节同型：npm ci&&build&&git diff --exit-code dist/＋失败 upload-artifact）。官方模板没有用任何 pre-push hook、没有任何自动补提交 bot。cheadergen 官方指南三条=①CI regenerate+diff 硬闸②「Document the regeneration command in CONTRIBUTING.md so contributors can run it locally before opening a PR」③--prune-orphans 防 stale 残留——与 (a) 逐字同构。thoughtbot：根因二分与本仓两次实证一致（「生成物进了 commit 但更新没进」），解法定位「if a computer generates a file, then a computer should be in charge（=CI 层）」，同时明示 CI 闸不消灭遗忘本身只是把学费变便宜；本地侧改善靠贡献流程文档。三独立信源（github.com 官方生态 deploy-pages/checkout/dependabot-action 同款 check-dist.yml × thoughtbot × cheadergen）同向。

**2.2 (b) 批量降频：否决——破坏已裁定分发契约**：ADR-0016＋D-067②「git-clone 无构建步＝可运行体必须随源」，per-change 再生是 D-140② 刚立的独立 commit 规约；批量降频在语义 commit 与 bundle commit 间造窗口期，窗口内 HEAD 自不含可运行体——翻 D-140②/D-067 且破坏 bisect 自含价值（R34-Q1 调研实证 check-in 派生对 bisect 有利 100% repeatable）。cheadergen「hybrid: commit at release time」折中案适用前提=「downstream 消费者从 release artifact 拿产物」，本仓分发面=git-clone 即用，前提不成立不可平移。

**2.3 (c) hook/bot 自动化：否决——三处硬伤全有业界实证**：①pre-push hook——.git/hooks 不入库、--no-verify 可绕过（HN #45527306 原文实证；SO/lazygit issue 佐证）；本仓 GitButler workspace 工作流与 git hook 生态兼容性另增风险；HN 共识「what matters is that failures don't get merged（=CI 层），not that they don't get committed」——hook 位置多余，CI 硬闸已住正确层位。②引 husky=为已由 CI 覆盖的检查引新依赖+安装时序问题，违零新机制。③CI bot 补提交——int128/update-generated-files-action 原文展示真实成本：write 权限 token、默认 GITHUB_TOKEN 不触发后续 CI（须 GitHub App token）、内置「last 5 commits by this action→error」防死循环、PR 补提交要故意 exit error 防 Renovate/Dependabot 自动合并——对单维护者仓=把「人忘」换成「bot 漂移不可见」，且 bot commit 混进语义链违 D-140② 可归因纪律；kentcdodds 原文批评同向：生成物 commit 混入历史=terrible git diffs。changeset version bot 式自动 commit 是发布流程（版本窗口本该批量），与逐 change 漂移修复语义不同，不构成同构先例。

**2.4 (d) 不动：部分否决——守卫有效但放任产生面缺口重复付费**：thoughtbot 明示 CI 闸「builds will take longer」＋失败回环成本；本仓已两次实证打回（20f7f5c/b244184），第三次不修 checklist 只是继续交学费。CI 硬闸保留（绝对不降级），但 (a) 零新机制零成本，(d) 无理由优于 (a)；且 (d) 与 D-144① 工序内化同构裁定相悖。

## 4) 推荐（可直接进裁定链的表述）

采纳 (a)＋守卫不降级：
1. closeout checklist 增一行「engine/src 或 engine/dist 触碰→前置跑 npm run build＋node scripts/check-dist.mjs 核对零 drift 再 commit」（D-144① 双层模式逐字平移）；
2. CI rebuild-diff（engine-ci.yml）保持 enforce 硬闸＋失败 upload-artifact，不降级不搬移；
