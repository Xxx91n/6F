# R51-Q4 调研题面 —— 存量非法指针处置（勘误时点与豁免边界的立法裁定）

## 背景

本仓=五尺度工程内容审计产品的 spec-level 规划+治理仓。承 D-188（指针法定形=SHA≥12hex+(\"subject\")＋存在∧锚线可达）＋D-189（严格层/宽层分层划界＋裸短码独承定位=违规）＋D-190（锚线声明制）。三裁均明「不溯既往（D-148③），存量走 D-181 勘误通道」。

悬而未裁=**存量处置的时点与豁免边界**。实证残留两处：
- **W8**：R51 预声明文件 §7 勘误节「变更 commit 指针」列写有 `201935fc`（已实证为 amend 孤儿孪生——cat-file -e 可验但不在任何分支祖先集；主线真 commit=`cb625c6491895e479a59ad5770d2748a8de70b32`）。此残留本身是立法动机——审计已建议「下轮勘误把主线 SHA 补进 §7」。
- **W6**：账本 T3 读数表（L1603 等位）残留 `(wmu)` 裸短码括注——per-session UI 码作唯一指代手段，按新法为严格层非法指针存量；其真实 SHA 需 `git log` 对表实证，可能已不可解析（会话漂移）。

约束面：D-181 勘误三字段（扩展描述／发现时点／变更 commit 指针——后者自身须按新法定形写）；D-146⑤ 追加不改写；D-148③ 不溯既往（不强制改写但可勘误）；勘误成本 vs 止血时点的权衡；勘误行本身是新指针纪律首次实战（演练价值）。

## 候选

(i) **本轮收口批顺手做**：两残留各落一条 D-181 勘误行（§7 追加主线真 SHA 注记；T3 表旁追加 wmu→SHA 映射或「不可解析」作废注记）——立止血＋勘误通道实战演练；
(ii) **排产下轮执行批**：登记欠账项与守卫件同批落——干净分层但残留存续窗口拉长；
(iii) **§7 做 T3 豁免**：T3 括注判宽层豁免——但 D-189② 已定 T3 列是严格层职能位，豁免=把同型缺口合法化（自拆台风险）；
(iv) **全仓普查后统一处置**：先跑全存量指针盘点（所有文书面 SHA/短码残存）再一次性勘误——穷尽但拖时点，且盘点本身是守卫件职责（先有人工普查则守卫落地即空转）。
