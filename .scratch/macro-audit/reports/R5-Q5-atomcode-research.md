## §1 执行摘要（Tl;dr）

**例外 1：①-1 报告补处置字段（B1.1）= 现在拍（2a 开工前）**——2a 缺口校准需要人工处置结论做 ground-truth 标签，是 25 行中唯一「晚拍会阻塞下游阶段开工」的行；纯 schema 增量、可逆，拖延纯付成本。
**例外 2：P5 目标市场方向 = 现在拍（仅方向层，凭据申请推阶段 3 开工门）**——25 行中最接近一扇门：publisher ID 创建后不可改（VS Code 官方原文「ID cannot be changed once created」）、审核/凭据有长铅垂期——铅垂期把 LRM 前移，「撞墙才拍」= 拍晚了。70% 置信规则支持方向先行。**⚠ 本例外与 D-012 条款存在边界冲突，见 §5。**

## §2 五板块要点

1. **Stage-Gate**（Cooper 官方全文）：gate = 前瞻性资源承诺点（go/kill/hold/recycle），非状态汇报会；PDMA 统计 kill 集中于第 2 gate（商业计划评审后）——阶段 2 正扮演该角色，P6/D2 判据在其后定案，之前拍必被推翻重拍。判据分 Must Meet（knock-out，=④组事实核验）/ Should Meet（打分，=图形资产类），拍板时点天然不同。
2. **两扇门映射**（fs.blog 全文 + Bezos 原句）：可逆决策尽快拍、不可逆尽可能晚拍；真正须按 LRM 推迟的是「不可逆 × 信息未到」交集。门型归类：一扇 = P5 市场、P2 对外 semver 承诺、①-3 .gitignore（准一扇）；两扇 = 其余。纯可逆项（CHANGELOG 口径等）现在拍不亏**但产物会被阶段 2 过时化→无收益只制造重做**，故仍挂门。
3. **LRM 边界**（codinghorror Poppendieck 原定义 + ben-morris 批评全文）：超 LRM 后决策由默认做出；LRM 无清晰 tipping point → 解药 = 决策日志 + 显式 trigger（绑定表方法论来源）；长铅垂期修正把 LRM 前移（P5 依据）；set-based design（SAFe）：P6/D2 正确姿势 = 登记候选判据集不收窄、等 2a/2b 数据收窄——不是推迟，是集合收窄。
4. **发行就绪清单时点**（CNCF graduation 模板 / npm staged publishing / VS Code 官方）：清单 = 申请门验收器（绑定提交动作），非立项拍死；VS Code PAT 2026-12-01 退役（官方，铅垂期实证）。
5. **失实登记项标准关闭动作**（Fowler ADR 原文）：**superseded 语义而非删除**——三步：①改状态不改内容（closed as superseded / overtaken by events，对应 GitHub "closed as not planned"）；②双向指针（旧条→新事实，新条→旧条）；③一行失实理由（「登记时 X 成立，实测 Y 后不再成立」）。删除/静默划掉 = 销毁决策日志。防退化兜底：触发事件后 1 工作日内必须拍；事件不来则以硬到期日重组改绑一次，再到期升级用户——禁静默滞留。
