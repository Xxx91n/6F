## 3) 分点结论（附特别裁决）

**①「收口 commit 对」有同型先例——成立（高置信，双源＋本地知识库三重）。**
- Kubebuilder/controller-tools #1108 官方维护者表述：「CI can merely check that the user **checked in any changed generated files as part of their commit**」——真源变更→派生件随 commit 收编，正是候选 (i) 的语义（本仓按 D-139/D-140② 拆为紧邻对，属同型变体）。
- Lincoln Loop towncrier 流水线：release 时 `towncrier build`→`git commit "Update CHANGES"`→`git tag` **同一原子批内紧邻收编**，不存在「changelog 漂到下个 release 周期」的常态。
- 本地知识库 R80-Q4（前轮 atomcode 调研）：「生成→diff→exit-code 的 CI 闸是权威落点」；R35-Q2：批量降频「在语义 commit 与 bundle commit 之间制造窗口期」被否——同一裁决逻辑直接支持 (i) 反对 (ii)。

**② 次轮收编的跨轮归属歧义——业界视为真风险（高置信，双源）。**
- Kent C. Dodds（一手批评文）：「you have to make sure that you only commit the built files when doing a release **and not with other file changes, otherwise your git diffs are going to be a huge mess and it'll be hard to identify when and what changes entered**」——「何时、何物进入」的归属识别正是 (ii) 的跨轮混同风险；他甚至要求贡献者 force push 掉混入 dist 的 commit。
- thoughtbot 2020：失步两根因（生成了没提交／提交了没生成）都属「该由计算机把关」的失败态，其解法是 CI 闸即时拦——不是挂到下轮批量收编。批量/降频收编在本仓 R35-Q2 已裁否（破坏每-commit 自含），(ii) 无新证据翻案。

**③ 派生信号豁免无生态先例——证伪成立（高置信）。**
- 三引擎检索均未找到「派生计数/摘录类信号入豁免清单」的成熟先例；唯一相邻形态是 .gitignore 掉生成物（那是「不 commit」路线，与本仓 bundle-in-repo 分发前提相反，R35-Q2 已裁前提不成立不可平移）。
- 本地知识库 R48-Q4 直接裁决过同型问题：「volatile-fields 清单仅收纯挥发族键名，**派生计数族明确禁入**」——(iii) 正是 D-179② 立法时已显式排除的通道，预期「无先例」未被证伪。

**④ 「除 X 外零 churn」口径——有惯例支持（中高置信）。**
- thoughtbot「code reviews shouldn't check the right bytes were placed in the right place」与 K8s verify-error 文案（"Generated code is out of date: … Please run make generated_files"）都是**把失真面显式命名为例外而非宣称全局干净**的表述形态；声明学上「clean except <enumerated derived signals>」与 K8s「anything that is properly gitignored won't cause a diff, but anything that is *supposed* to be checked in but is different will be caught」同构——豁免枚举在前、真信号闸在后。口径改述有惯例面，但只改口径不消除 drift 本体，故 (iv) 只作 (i) 的报告面配套。

**账本冲突扫描**：(i)+(iv) 与 D-140②（独立 bundle commit——(i) 正是其兑现）、D-179②（派生信号禁豁免——(iii) 被否，零冲突）、D-179④（无自动 discard——(i) 保留人工判/独立收编）、D-139（语义/生成物分 commit）、D-144①④、D-146⑤、D-148③（新规程自落盘 commit 起生效，存量豁免）、D-177——**全部相容，无需任何 revised**。

## 4) 推荐（可直接进裁定链的表述）

**裁 (i)＋(iv) 复合，置信度：高**：
1. 收口工序末尾钉死「语义收口 commit → regen census → 独立 bundle commit 紧邻收编」，报告口径同轮改述「除已收编真实语义信号件外零 churn」；
2. (ii) 显式否决（跨轮归属歧义为业界实证真风险），(iii) 显式驳回入去向表（撞 D-179②，无先例证伪成立）；
3. 按 D-148③，新工序自落盘 commit 起生效，落盘轮自身豁免。
